# 단계별 진행 계획

## 확정 요구사항

- 원본 부트로더 / MAIN / SUB 코드는 절대 수정하지 않는다. 필요한 개발은 복사본에서만 수행한다.
- 초기 화면은 Fault Emulator 카드형 선택 화면을 참고한 부트로더 / TEST 모드 선택이다.
- MAIN: 물리 로터리 상태 실시간 표시, FAULT OPEN/CLOSE, 펌웨어 업데이트 검사.
- DIO: 물리 ID DIP 상태 실시간 표시, 펌웨어 업데이트 검사.
- SW8, 통신 검사, 스위치 자동 PASS/FAIL은 제외한다.
- HEX를 선택해 업데이트한다. 동일 펌웨어가 현재 보드에 있으면 기록을 생략하고 “이미 최신 버전입니다.”라고 표시한다.
- 비교는 중복 업로드 방지를 위한 내부 처리다. 별도의 비교 결과 화면을 만들지 않는다.
- 기록 및 부트로더 검증 완료 응답을 받으면 “펌웨어 업데이트 성공”으로 판정한다. 운용 기능 검사는 하지 않는다.
- 두 화면의 업데이트 처리 코드는 공유한다.

## 단계

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| 1 | 원본 기준 기록, 별도 복사본, PC 골격, 개발 환경 확인 | 준비 산출물과 원본 불변 검증 |
| 2 | 초기 선택 및 MAIN/DIO TEST 화면 | 화면 이동과 상태 표현 검토 |
| 3 | MAIN 로터리 조회, FAULT 제어 | PC 연결 기능과 복사본 코드 구현 완료; 실물 확인 대기 |
| 4 | MAIN HEX 업데이트, 동일 펌웨어 생략 | PC 업데이트 서비스 구현 완료; 실물 기록 확인 대기 |
| 5 | DIO USB 부트로더, ID 조회 | ID 매핑 및 PC 수신 준비 완료; USB CDC/부트로더 생성 기반 대기 |
| 6 | TEST 모드 MAIN 펌웨어 확인 | MAIN 부트로더 READ_FLASH 비교 완료; 실물 확인 대기 |
| 7 | DIO 읽기 전용 펌웨어 정보 조회 | DIO USB CDC 및 PC 연결 구현 완료; 실물 확인 대기 |
| 8 | USB 자동 실행·연결 해제·재연결·배포 통합 확인 | 전체 흐름과 원본 불변 검증 |

1~7단계 코드 구현을 완료했다. 3~7단계 실물 보드 확인, Windows 로그인 자동 실행 등록, 배포 패키지 정리가 남아 있다.

## 다음 단계에 반영할 기술 사항

- MAIN 로터리: PC0~PC3, 원본 코드 명칭 CAN_ID4~7. 입력 4비트와 로터리 값 표시, 약 100ms 갱신 목표.
- DIO: ID_SET1=PA0, ID_SET2=PC15. 회로도 ID 표와 코드의 비트 순서 차이는 실물 기준으로 확인하여 복사본에 반영한다.
- MAIN FAULT: PE2 Low=OPEN, High=CLOSE. K1 접점 측정 위치는 TB18-1 EXT_COM ↔ TB18-2 EXT_FLT.
- FAULT 명령 응답은 실제 도통 판정이 아니다. 사용자가 직접 측정한다. 자동 출력 제어와 TEST 명령의 충돌, 종료·연결 두절 처리를 설계한다.
- 현재 MAIN USB에는 스위치 조회/FAULT 수동 명령이 없으므로 보드 복사본 개발이 필요하다.
- MAIN 기존 업데이터는 BIN 입력과 A/B 슬롯별 이미지를 사용한다. HEX 주소를 보존하고 슬롯에 맞는 파일을 사용해야 한다.
- DIO는 현재 USB 부트로더가 없다. 128KB 플래시 설정에 맞춘 영역 설계와 최초 프로그래머 설치가 필요하다.
- 보드 기록과 하드웨어 검사는 해당 단계에서 별도로 진행한다. 1단계에는 장치 접속·출력 제어·플래싱을 하지 않는다.
