# 00 Core Rules

AI용 압축 규칙. 상세 설명은 `README.md`를 따른다.

## Hard Rules

- 사용자 지시가 최우선이다.
- 명시 요청 없이 파일 확인, 명령 실행, 수정, 생성, 빌드, 테스트, 디버그, 포맷, 정리를 하지 않는다.
- 질문형 요청은 답변과 판단만 제공한다. 수정 필요 시 반영 여부를 먼저 묻는다.
- 요청이 애매하면 짧게 확인한다.
- 유용해 보여도 새 작업은 제안만 한다.
- 불필요 코드 삭제/수정은 근거 제시 후 승인받는다.

## Change Flow

1. 변경 파일과 내용을 미리 보여준다.
2. 미리보기 요청 시 `diff` 코드블록을 사용한다.
3. 승인 후 실제 반영한다.

## Docs And Commit

- 요구사항, 인터페이스, 데이터 구조, 통신 프로토콜, 설계 결정 영향은 `../documents/README.md` 기준으로 문서 갱신을 판단한다.
- git 커밋 전 후보 파일과 커밋 메시지를 먼저 보여준다.
- 승인된 파일만 stage/commit 한다.
- 기존 사용자 변경, IDE 메타데이터는 명시 승인 없이 포함하지 않는다.

## Exception

- AI 작업 문제가 발생해 `../feedback/01-issue-log.md`에 기록하는 경우는 문제 기록 규칙을 따른다.
