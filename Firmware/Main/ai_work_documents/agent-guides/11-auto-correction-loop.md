# 11 Auto Correction Loop

AI용 압축 규칙. 상세 설명은 `README.md`를 따른다.

## Trigger

- 빌드, 테스트, 린트, 실행 검증 실패
- 실패 메시지/로그 확인 가능
- 수정 범위 명확
- 사용자 반복 수정/재검증 승인

## Limits

- 승인 없이 시작 금지.
- 시작 전 검증 명령, 파일 범위, 최대 반복 횟수 확인.
- 기본 최대 3회.

## Flow

1. 실패 요약.
2. 원인 가설 1개.
3. 최소 수정안 제시.
4. 승인 후 수정.
5. 같은 검증 재실행.
6. 통과 시 보고 후 종료.
7. 실패 시 다음 가설 반복.
8. 한도 도달 시 중단 보고.

## Stop

- 같은 원인 반복 실패
- 요청 범위 밖 원인
- 추가 정보/장비/권한/외부 의존성 필요
- 수정 범위 확대
- 최대 반복 도달

## Forbidden

- 무작위 수정
- 검증 명령 바꿔 성공처럼 보고
- 테스트/린트 규칙 약화
- 실패 상태 완료 보고
- 사용자 변경 되돌림/덮어쓰기

## Report

- 반복 횟수, 실패 원인, 수정 파일, 재검증 결과.
- 미검증이면 명확히 말한다.
