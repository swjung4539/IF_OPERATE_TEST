# Documents Guide

이 폴더는 프로젝트 요구사항, 설계, 인터페이스, 데이터 구조, 프로토콜 같은 프로젝트 관리 문서를 작성하는 곳이다.

## 사용 원칙

- 프로젝트 요구사항, 설계, 인터페이스, 데이터 모델, 프로토콜, 설계 결정, 구현 계획처럼 계속 관리하는 문서는 이 폴더에 둔다.
- 시퀀스 다이어그램, 설명용 다이어그램, 검토 보고서, 최종 요약처럼 결과물 성격의 산출물은 `ai_work_documents/artifacts/`에 둔다.
- 외부 자료, 데이터시트, 기존 사양서처럼 읽기 전용 참고 자료는 `ai_work_documents/references/`에 둔다.
- AI 작업 방식이나 추가 지시는 `ai_work_documents/agent-guides/`에 둔다.
- 문제 기록이나 피드백은 `ai_work_documents/feedback/`에 둔다.
- 모든 `.md` 파일은 UTF-8 인코딩으로 작성하고 저장한다.

## 권장 문서 구조

```text
documents/
├── 01-requirements.md        # 요구사항 정의
├── 02-architecture.md        # 시스템 구조 설계
├── 03-interfaces.md          # 인터페이스 정의
├── 04-data-model.md          # 데이터 구조 / 상태 정의
├── 05-protocol.md            # 통신 프로토콜 정의
├── 06-design-decisions.md    # 주요 설계 결정 기록
└── 07-implementation-plan.md # 구현 단계 / 검증 / SDD 계획
```

## 문서별 용도

각 문서는 항목을 하나만 쓰는 문서가 아니라 여러 항목을 ID 기반으로 누적 관리하는 문서다. 사용자에게 전달하는 결과 산출물은 `ai_work_documents/artifacts/`에 별도로 둔다.

권장 ID 접두사는 다음과 같다.

- `REQ-`: 요구사항
- `ARCH-`: 아키텍처 항목
- `IF-`: 인터페이스
- `DATA-`: 데이터 모델
- `PROTO-`: 프로토콜 항목
- `DEC-`: 설계 결정
- `IMP-`: 구현 단계

### 01-requirements.md

사용자 요구사항, 기능 요구사항, 비기능 요구사항, 제약 조건, 완료 기준을 ID 기반으로 누적 관리한다.

### 02-architecture.md

시스템 구성, 주요 모듈, 책임 분리, 데이터 흐름, 외부 의존성을 ID 기반으로 누적 관리한다.

### 03-interfaces.md

모듈 간 함수, API, 메시지, 입출력, 에러 처리 규칙을 ID 기반으로 누적 관리한다.

### 04-data-model.md

주요 데이터 구조, 상태 값, 설정 값, 저장 형식, 메모리 배치를 ID 기반으로 누적 관리한다.

### 05-protocol.md

UART, CAN, USB, Modbus 같은 통신 프레임, 명령, 응답, 타임아웃, 예외 처리를 ID 기반으로 누적 관리한다.

### 06-design-decisions.md

중요한 설계 결정, 선택 이유, 대안, 포기한 선택지, 결정 일자를 ID 기반으로 누적 관리한다.

### 07-implementation-plan.md

확정된 요구사항과 설계 결정을 실제 코드에 반영하기 위한 단계별 구현 순서, 완료 기준, 검증 기준, SDD/subagent 적용 계획을 ID 기반으로 관리한다.

## 작성 형식

각 문서는 다음 형식을 기본으로 사용한다.

```markdown
# 문서 제목

## 목적

이 문서가 다루는 범위를 적는다.

## 내용

요구사항, 설계, 인터페이스 등 핵심 내용을 적는다.

## 제약 사항

하드웨어, 성능, 일정, 호환성, 외부 의존성 같은 제약을 적는다.

## 미결정 사항

아직 결정되지 않은 내용이나 사용자 확인이 필요한 내용을 적는다.

## 변경 이력

- YYYY-MM-DD: 변경 내용
```

## AI 사용 규칙

AI는 사용자가 명시적으로 요청한 경우에만 이 폴더의 문서를 생성하거나 수정한다.

문서 작성 중 요구사항이 애매하면 추측으로 채우지 않고 미결정 사항에 기록하거나 사용자에게 확인한다.

`ai_work_documents/references/`의 자료를 참고할 수는 있지만 수정하지 않는다.

구현 작업을 시작하기 전에는 `07-implementation-plan.md`를 기준으로 단계와 검증 기준을 확인한다.

구현 작업이 진행 중일 때는 진행 중 상태를 문서와 분리해 관리하고, 변경 사항이 있을 경우 결과를 관련 `.md` 파일에 반영한다.
